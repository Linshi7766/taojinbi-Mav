# taojinbi-Mav

使用 `uiautomator2` 和 OCR 辅助完成淘宝任务。所有命令均从项目根目录运行：

> 本项目源自 [czl0325/coin11-tb](https://github.com/czl0325/coin11-tb)（Apache-2.0），
> 在其基础上延续并大幅重写：淘金币相关能力已重构为纯 OCR 安全浏览实现，
> 旧版多任务资产不再包含。

```powershell
Set-Location '<项目根目录>'
```

## 环境与测试

项目使用工作区内的 `.venv`。如果该环境已经存在，不需要重复安装；只有依赖缺失时才执行：

`.venv` 是本项目唯一受支持的测试/验证解释器；系统 Python 可能缺少 `lxml`/`cv2`，其结果不作为验收基线，依赖缺失时请按现有 `requirements.txt` 安装到 `.venv`。

```powershell
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

离线运行测试：

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -t . -q
```

## 入口

- `scripts/run_taojinbi.py` 是唯一的真机自动化入口，仅处理下表注册的三种任务。普通执行时若当前不在任务弹窗，会在淘金币页面自动点击“赚更多金币”打开弹窗并校验列表锚点；`--dry-run` 不会导航，仍需手动打开“赚金币抵钱”任务弹窗。打包与公开发布仍未完成。
- `taojinbi_task_strategies.py`：已经通过安全筛选后的任务交互策略；信息流任务只停留/上滑，“搜一搜”只点击搜索发现关键词并在结果页上下滑动。该模块不负责放行任务、进度完成判定或批次执行。
- `淘宝多任务执行.py` 是旧版 UIAutomator 启动器，不属于当前 OCR 真机运行合同。不要运行 `淘宝多任务执行.py` 或其他入口替代标准 CLI。

从项目根目录启动唯一 CLI；把尖括号内容替换为真实设备序列号，按需选择任务和数量：

```powershell
& .\.venv\Scripts\python.exe .\scripts\run_taojinbi.py --serial <设备序列号> --task featured_goods --gpu --max-tasks 1
```

## 循环守候（推荐日常用法）

单次 CLI 只检查一轮；`scripts/wait_for_task.py` 在其外层提供"只要有任务就一直跑"的守候循环——每轮仍完整调用唯一 CLI（全部安全边界生效），循环层只做调度：

```powershell
& .\.venv\Scripts\python.exe .\scripts\wait_for_task.py --serial <设备序列号>
```

- 默认等任意已注册任务（`--task` 可指定单一类型）；命中即执行**一个**任务
- 三档拟人节奏：未完成轮次间 1–3 分钟、做完一个任务 5–15 分钟、空窗检查 3–8 分钟
- 自动收场：一个完整守候阶段（8 轮）无任务即结束；整场 240 分钟硬上限（`--session-deadline-min` 可调）
- 异常即停：任何非零退出码立即结束守候，人工核对后再重启
- 会话监控面板与 OCR 推理 sidecar（省去每轮模型冷启动）自动拉起，`--no-panel` / `--no-ocr-sidecar` 可关

允许的任务参数为 `--task search`、`--task hashtag` 或 `--task featured_goods`；省略 `--task` 时扫描全部已注册任务。真机运行统一显式传 `--gpu`，逐步扩大前再调整 `--max-tasks N`。

Windows 上通过该 CLI 正式运行时，会自动启动 `python -m taojinbi_mav.runtime.watch` 实时进度面板窗口。面板读取 `logs/` 中的 JSONL 事件日志，并在运行结束后自动关闭；这是预期行为。不要传 `--no-watch`，也不要主动关闭进度面板。

不要通过 `import` 直接调用 `run_ocr_entry()` 运行真机任务；这种方式不会启动标准进度面板，而且会绕过 CLI 的统一参数、日志和退出码行为。

默认最多执行 1 个安全浏览任务；传 `--max-tasks 0` 只检查入口不执行任务。设备序列号由 `--serial` 或环境变量 `TAOJINBI_DEVICE_SERIAL` 提供；**仓库不保存任何默认设备地址**，两者都缺失时以退出码 3 安全失败且不连接设备。CLI 仍支持 CPU 作为兼容选项，但本项目后续真机自动化统一使用 `--gpu`。未连接设备、账号处于风控冷却期或未完成人工确认时，不要启动真实任务。

## 安全范围

当前离线实现只注册以下三个任务模块：

| 模块 | 标题结构 | 当前执行策略 | 发布状态 |
|---|---|---|---|
| 搜一搜 | `搜一搜…` | 搜索发现关键词后仅上下滑动 | 真机执行通过，金币到账已确认 |
| 看看# | `看看#…` | 信息流停留与上滑 | 真机执行通过，金币到账已确认 |
| 发现精选好物 | 精确标题 | 信息流停留与上滑 | 真机执行通过，金币到账已确认 |

- 标准注册表的 OCR 发现和默认主入口的精确回定位都必须取得 profile；表外任务无法经注册表获得执行资格，即使标题或描述包含“浏览”也不例外。默认扫描不会为它们产生候选，会安全跳过并以空/安全汇总结束；只有直接调用 `run_one_safe_browse_task(未知标题)` 时，才会在任何设备动作前返回 `unsupported_task`。仓库仍保留用于私有历史兼容和测试的“好物沉浸看”专用候选/执行函数；它们不属于三模块标准主入口，计划在公开净导出或后续清理时删除。
- `搜一搜`、`看看#` 可以在 OCR 漏读时省略同行“浏览”证据；`发现精选好物` 必须取得同行“浏览”证据。只有 `看看#` 启用动态分母和轮换标题身份。
- 头条、支付宝、蚂蚁森林等第三方应用任务会跳过。
- 下单、购买、邀请、充值、助力、游戏、外卖、红包等交易或高风险特征会跳过；外部红包、抢红包和带交易描述的任务均默认跳过。
- 注册任务进入信息流后只停留和上滑；“搜一搜”随机选择“搜索发现”关键词后只在结果页上下滑动，绝不点击商品详情。所有流程均不点击加购、购买、下单或验证码控件；包名、OCR 证据或入口二次校验失败时安全退出。
- 如果任务已进入并浏览、返回后任务行暂时消失，OCR 入口会最多两次退出到淘金币页面，动态点击“赚更多金币”、等待列表并滚动一屏后复查；只有同一注册身份、分母未变化且进度未回落的未完成任务才自动续跑。分母变化或进度回落表示任务周期已经轮换，立即停止且不进入新周期；两次仍找不到也停止当前任务，不点击下一个任务。

本阶段已完成三模块注册表和运行时加固（deadline/CLI、`--dry-run`、脱敏结构化日志、退出码与 `Ctrl+C`），详见下方“公开版运行合同”；公开 CLI 的只读 dry-run 真机验收已通过，`搜一搜`、`看看#` 与 `发现精选好物` 均已完成真机执行并确认金币到账；打包与依赖元数据、干净导出和公开发布仍未完成。

## 公开版运行合同

本节说明公开 CLI 的运行前提、支持范围、时间预算、退出码、日志与隐私边界。只读 dry-run 真机验收已通过；真实执行仍受任务随机刷新、账号状态和风控影响，使用前必须人工确认当前页面与授权范围。

### 运行前提

- 普通执行：把手机停在**淘金币页面**（能看到“赚更多金币”）即可，脚本会自动打开“赚金币抵钱”任务弹窗；当前已在弹窗列表页时直接使用。脚本不会导航到淘金币页面本身，也不会在淘宝以外的页面操作。
- `--dry-run`：不会导航或打开弹窗，运行前必须**手动打开淘宝“赚金币抵钱”任务弹窗**并停留在列表页。
- `--dry-run` 是只读检查：只扫描当前可见一屏，不会点击、不会滑动、不会返回、不会领取奖励，也不会读取任务列表以外的内容。
- 未连接设备、账号处于风控冷却期或未完成人工确认时，不要启动真实任务。

### 支持模块（仅三项）

| 模块 | 脱敏报告格式 | 执行策略 |
|---|---|---|
| 搜一搜 | `搜一搜…` | 随机选择“搜索发现”关键词后仅上下滑动，不点击商品 |
| 看看# | `看看#…` | 信息流停留与上滑 |
| 发现精选好物 | 精确标题 | 信息流停留与上滑 |

### 已移除任务（不在支持列表）

拍立淘、酒店超抵、去省钱卡领红包、淘金币充话费 等任务已从支持列表移除。默认扫描不会为这些标题生成候选，会安全跳过并以空/安全汇总结束；只有直接调用 `run_one_safe_browse_task(未知标题)` 才会在设备动作前返回 `unsupported_task`。

### 时间预算与中止

- 默认时间预算：`--dry-run` 2 分钟、单任务 20 分钟、整次运行 30 分钟。
- 超时或首次 `Ctrl+C` 后，脚本会先尝试安全返回任务列表（最多 10 秒恢复宽限）再停止，不会自动开始下一个任务。
- 协作式时限：脚本只在动作与等待边界检查时间，不使用可能在后台继续动作的超时线程；因此不能保证硬中断单次卡死的 ADB/OCR 调用，只能通过动作边界检查尽快停止。
- `Ctrl+C` 两阶段退出：dry-run 中直接退出；execute 中第一次触发进入 10 秒恢复窗口，恢复期间再次触发立即退出且不再点击或滑动。

### 退出码

`0` 正常完成 / dry-run 成功 / 无候选；`1` 已执行但未确认完成；`2` 参数错误；`3` 设备/OCR/入口检查失败；`4` 安全边界停止；`5` 超时；`130` 用户 `Ctrl+C` 中止。

### 日志与隐私边界

- 控制台输出可读中文进度；同时在 `logs/` 写入 UTF-8 JSON Lines 事件日志。
- 日志不记录 OCR 原始截图、设备序列号或商品名称；任务统一使用脱敏标签（如 `看看#…`、`搜一搜…`）。

### 离线测试与只读 dry-run

离线运行测试：

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -t . -q
```

只读 dry-run（需要复核时，在用户授权后手动打开弹窗再执行）：

```powershell
& .\.venv\Scripts\python.exe ".\scripts\run_taojinbi.py" --dry-run
```

dry-run 命令会连接 ADB 并 OCR 读屏，但**不会产生任何 UI 动作**；它只验证当前可见一屏的识别、脱敏报告、退出码与零动作。普通 execute 真机测试不属于本阶段验收步骤。
