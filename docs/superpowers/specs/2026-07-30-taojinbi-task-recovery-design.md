# 淘金币任务恢复与诊断设计

## 目标

修复淘宝页面切换期间 `get_current_app()` 返回空值导致的
`argument of type 'NoneType' is not iterable`，并避免任务控件尚未加载时被连续两次
误判为“没有可点击按钮”而提前退出。

修复同时让脚本能够逐屏发现淘宝内部纯浏览任务，但不执行外部应用、交易或互动类
任务，不绕过安全黑名单，也不加入 OCR 坐标点击。

## 方案

### 1. 安全读取当前应用

在 `utils.py` 中提供一个小型、可单元测试的判断函数。只有包名是非空字符串时，
才执行包名包含判断。`task_loop()` 遇到空包名时短暂等待并继续轮询，而不是抛出
`TypeError`。

### 2. 任务页恢复

`淘金币任务.py` 捕获单个任务执行异常后调用现有 `back_to_task()`，保证下一轮从
任务列表重新开始。恢复失败时保留错误日志，不把异常当成“任务已完成”。

返回任务页后，在有限时间内轮询任务按钮。轮询只等待现有 UI 控件出现，不自动点击
额外按钮，不无限重试。

### 3. 连续失败计数

`error_count` 表示“连续未发现可执行任务”的次数：

- 成功点击任务、领取奖励或点击“点击得”后重置为零；
- 页面仍在加载时不增加；
- 确认任务列表已加载但没有候选任务时才增加；
- 达到现有阈值 2 后退出。

这样保留原项目的退出策略，同时消除累计失败导致的提前退出。

### 4. 可解释诊断

查找任务按钮时分别统计并输出：

- 页面上匹配到的任务按钮数；
- 因安全黑名单被跳过的任务名称；
- 因同名任务已尝试两次被跳过的任务名称；
- 因无法读取相邻任务名称而跳过的按钮数；
- 完全没有暴露为 `android.widget.Button` 的情况。

日志不得包含账号、手机号、Cookie 或其他个人信息。

### 5. 浏览任务安全分类

候选任务必须同时满足允许条件和排除条件：

- 任务名称或描述包含“浏览”“逛宝贝”“精选好物”“拍立淘”等淘宝内部浏览特征；
- 不包含头条、支付宝、蚂蚁森林等外部应用名称；
- 不包含“下单、购买、邀请、充值、助力、游戏、红包、外卖”等交易或互动特征；
- 能够读取完整任务名称或描述；读取失败时默认跳过。

现有安全黑名单继续作为第二层排除规则。按钮文字“去完成”本身不能证明任务安全，
必须先完成任务文本分类。“快速得大量金币”这类描述同时包含“下单”的任务必须跳过。

### 6. 可滚动任务列表

任务发现采用“逐屏扫描、找到一个就执行”的流程：

1. 读取当前可见任务，输出分类结果；
2. 如果存在安全的淘宝内部浏览任务，执行第一个；
3. 返回任务列表并等待控件稳定，再从当前可见区域重新扫描；
4. 如果当前屏没有安全候选任务，向列表底部方向滑动一屏；
5. 保存每屏可读取的任务标识集合；连续两次滑动后集合没有变化，判定到达底部；
6. 到达底部且没有候选任务时，才增加连续失败计数。

扫描状态只在本次运行期间保存在内存中。任务标识由任务名称和可见进度文本组成，
不使用屏幕坐标作为唯一标识。单个任务最多尝试两次，防止返回位置变化造成重复执行。

### 7. 计数语义

保留现有 `finish_count`，但将结束日志明确为“已领取奖励次数”，避免把它误解成
浏览任务数量。另记录本次成功点击的任务数，仅用于本地终端汇总。

## 测试

新增无需连接手机即可运行的单元测试，覆盖：

1. 包名为 `None` 时，应用判断返回假而不抛异常；
2. 成功动作会把连续失败计数重置为零；
3. 页面加载中不会增加失败计数；
4. 已加载且无候选任务时失败计数增加；
5. 诊断分类能区分黑名单、重试上限和任务名缺失；
6. 只接受淘宝内部纯浏览任务；
7. 含外部应用或交易关键词的任务即使按钮为“去完成”也会被拒绝；
8. 新的一屏出现新任务时继续扫描；
9. 连续两屏任务标识不变时判定列表到底；
10. 返回任务页后不会重复执行已达到重试上限的任务。

测试使用标准库 `unittest`，不新增依赖。手机验证只确认：

- “发现精选好物”能被识别为候选任务；
- “拍立淘逛感兴趣的宝贝”能被识别为候选任务；
- 任务列表可以自动向下扫描并在到底时停止；
- 头条、支付宝、蚂蚁森林和带“下单”的任务均被跳过；
- 页面切换瞬间没有 `NoneType` 异常；
- 异常恢复后脚本能够回到任务列表；
- 不自动执行购买、下单、邀请、充值等黑名单任务。
