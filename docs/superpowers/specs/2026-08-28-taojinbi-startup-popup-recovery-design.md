# 淘金币正式执行启动时安全打开任务弹窗设计

## 背景与目标

当前正式执行入口 `_execute_scan()` 要求启动时已经位于“赚更多金币”任务弹窗；如果手机停留在淘金币首页，它会直接返回 `list_anchor_missing`。项目已有 `_reopen_task_popup()`，能够在淘宝安全页面中通过 OCR 唯一识别“赚更多金币”、动态点击并验证任务列表锚点，但该逻辑目前只用于任务完成后的页面恢复。

本改动把现有安全 helper 接入正式执行启动流程，使脚本在淘金币首页启动时能够自行打开任务弹窗。它不扩大任务白名单，不增加坐标点击，不绕过验证码或风控。

## 方案选择

采用“在 `_execute_scan()` 内复用 `_reopen_task_popup()`”方案：改动最小，执行模式和只读模式边界清晰，并复用已经过真机验证的失败关闭逻辑。

未采用的方案：

- 在 CLI `main()` 中预先点击：会把设备连接、只读模式和正式执行的职责混在一起。
- 引入通用页面导航状态机：当前只有一个明确缺口，抽象范围过大。

## 行为设计

正式执行启动时：

1. 先使用现有 `on_task_list()` 检查任务列表。
2. 如果已经在任务弹窗，保持原流程，不产生额外点击。
3. 如果不在任务弹窗，读取屏幕尺寸并调用 `_reopen_task_popup()`。
4. helper 只有在淘宝安全页面、且“赚更多金币”OCR 结果唯一时才会点击；点击后必须检测到任务列表锚点。
5. 打开失败、页面不安全、识别不唯一或发生异常时，返回启动失败并停止，不继续扫描或执行任务。

只读 `--dry-run` 保持现有零动作合同：不自动打开弹窗，不点击、不滑动、不返回；若启动时不在任务弹窗，继续返回 `list_anchor_missing`。

Python 进度监控保持默认开启；本改动不改变 `--no-watch` 的显式关闭能力。后续真机执行命令默认不传该参数。

## 错误与结果口径

- 首次任务列表检查抛出异常：保持 `task_list_check_failed`。
- 自动打开 helper 返回 `False`：返回 `list_anchor_missing`，兼容现有退出码和外部调用。
- 获取屏幕尺寸或调用 helper 抛出异常：失败关闭，返回 `task_list_check_failed`。
- 自动打开成功：进入原有 `run_safe_browse_tasks()` 流程。

## 测试策略

严格按 TDD 实施：

1. 先新增正式执行不在列表时调用 `_reopen_task_popup()` 并继续执行的测试，确认在现有代码上因未调用 helper 而失败。
2. 新增 helper 返回 `False` 时保持启动失败、且不进入任务执行的测试。
3. 保留并运行 dry-run 零 UI 动作测试，证明只读路径没有被改变。
4. 运行相关运行时测试、完整离线测试和 `git diff --check`。

测试使用标准库 `unittest` 与现有 mock 结构，不新增依赖，不自动执行真实手机上的全部任务。
