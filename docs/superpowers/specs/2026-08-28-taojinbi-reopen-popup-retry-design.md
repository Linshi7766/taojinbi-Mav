# 淘金币任务弹窗重开入口有界重试设计

## 背景与根因

精选好物真机任务已经能够被识别并进入浏览，但本轮在浏览收尾后返回淘金币首页时，`_reopen_task_popup()` 因一次 OCR 没有可靠读到唯一的“赚更多金币”入口而返回 `False`，最终记录为 `no_safe_control`。现有日志与只读诊断表明设备仍在淘宝安全包内；失败点是入口加载/OCR 短暂抖动，不应通过任意页面返回或固定坐标绕过。

## 目标与非目标

目标是让任务完成一轮浏览后，入口 OCR 的瞬时缺失不会立即终止本轮；在安全条件满足时进行少量重试，并继续验证任务弹窗锚点。

非目标：

- 不扩大淘宝页面身份判定，不对未知页面盲目按返回。
- 不使用固定坐标或 OCR 失败时的坐标兜底。
- 不改变任务白名单、策略、动态分母或单任务上限。
- 不绕过验证码、风控或外部应用任务。

## 方案选择

采用在现有 `_reopen_task_popup()` 内增加最多两次入口识别尝试的方案。每次尝试都重新读取当前屏幕并经过淘宝包名、风控和唯一文本校验；只有取得安全入口边界框后才允许 `safe_tap()`。点击后继续复用已有的任务列表重试验证。

未采用的方案：

- 放宽 `_safe_back_to_coin_page()` 到任意淘宝页面：不能解决重开入口 OCR 瞬时缺失，并会扩大返回范围。
- 直接重试固定坐标：违反动态 OCR 点击和失败关闭约束。

## 行为设计

`_reopen_task_popup(d, reader, screen, deadline=None)`：

1. 最多尝试 `ENTRY_VALIDATION_RETRIES + 1` 次（当前为 3 次，与入口校验上限一致）。
2. 每次尝试先检查 deadline，再截图/OCR。
3. OCR 为空、当前包不是淘宝或命中风控词时立即失败关闭，不继续点击。
4. 只有唯一识别到“赚更多金币”且 `safe_tap()` 成功时才点击。
5. 点击后等待页面稳定，并通过现有 `retry_entry_validation()` 验证“赚金币抵钱”任务列表锚点。
6. 列表验证成功立即返回 `True`；验证失败时不重复盲点，进入下一次尝试前必须重新读取屏幕并再次满足全部安全条件。
7. 所有尝试耗尽返回 `False`，调用方继续沿用 `no_safe_control`/`list_anchor_missing` 等既有失败口径。

只读 `--dry-run` 路径不调用该 helper，保持零点击、零滑动、零返回。进度监控默认行为不改变。

## 测试策略

严格按 TDD：

1. 新增测试：第一次入口 OCR 无唯一 action，第二次出现唯一 action，helper 应成功点击一次并返回任务列表验证结果；在当前实现上应失败。
2. 新增测试：所有入口尝试均无唯一 action 时返回 `False` 且不点击；验证有界上限。
3. 新增测试：任一重试屏幕不在淘宝或命中风控时立即停止，后续不再点击。
4. 保留现有 `_reopen_task_popup()` 成功、失败和 dry-run 零动作测试。
5. 运行相关运行时测试、完整离线套件和 `git diff --check`；不自动执行真实手机上的全部任务。
