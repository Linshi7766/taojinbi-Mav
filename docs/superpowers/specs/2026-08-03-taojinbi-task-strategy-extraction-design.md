# 淘金币任务策略层拆分设计

## 背景

当前 OCR 主入口 `淘金币系/taojinbi_ocr_immersive.py` 同时负责设备安全门、任务列表导航、任务消失恢复、具体任务浏览动作、进度状态机适配和批次汇总，已经达到约 850 行。任务分类本身位于 `taojinbi_ocr_ui.py`，但“普通信息流浏览”和“搜一搜”两套具体动作仍嵌在运行入口中，导致任务策略、页面导航和运行编排边界不清。

本次只拆分任务策略层，不改变已经验证的白名单、安全过滤、进度判定、刷新恢复和真机交互参数。

## 目标

- 新建单一策略模块 `taojinbi_task_strategies.py`，集中两类任务策略的选择和一次浏览动作。
- 将普通信息流浏览与搜索发现浏览从 OCR 运行入口中移出。
- 让 OCR 运行入口只负责进入任务、调用策略、返回列表、进度回读、刷新恢复和结果汇总。
- 保持核心进度状态机为无设备、无 OCR 的纯逻辑模块。
- 对未知策略、OCR 不可靠、安全检查失败和离开淘宝继续失败关闭。
- 使用标准库 `unittest` 按 TDD 完成迁移，不新增依赖。

## 非目标与安全边界

- 不修改允许任务白名单、危险词或外部应用词。
- 不新增或扩大任何任务类型。
- 不改变 `看看#` 动态分母、标题轮换和任务身份规则。
- 不改变任务消失后最多两次刷新、单任务停止边界或 `--max-tasks` 默认值。
- 不改变现有停留时间、滑动距离、等待时间和进度完成判据。
- 不执行第三方、交易、充值、助力、游戏、红包抢领或外卖任务。
- 不绕过验证码或风控，不增加商品详情点击。
- 不在本次重构中统一 OCR 与旧控件树的全部分类常量。
- 不移除旧入口；旧入口保持兼容。

## 当前策略分类

### 普通信息流浏览 `feed_browse`

适用于已经通过安全筛选、且不需要搜索前置动作的纯浏览任务，例如好物、发现精选、拍立淘、看看#和逛逛金币类任务。

单轮行为保持现状：按照运行入口计算的 `browse_count` 停留并上滑；每次动作前确认仍在淘宝。该策略不点击信息流中的任何内容。

### 搜索发现浏览 `search_discovery_browse`

仅适用于“搜一搜”结构任务。单轮行为保持用户确认的真实流程：

1. OCR 确认搜索入口页；
2. 从“搜索发现”标题下方的安全候选中随机点击一个关键词；
3. 有界等待搜索结果奖励流出现；
4. 在结果页上滑一次并下滑一次；
5. 每次滑动后重新确认淘宝包名和无风控文本；
6. 不点击任何商品或进入商品详情。

### 不属于任务动作策略的规则

`看看#` 的动态分母、后缀轮换和刷新后的任务身份判定属于进度与身份策略，继续由现有 OCR 运行入口和核心状态机处理，不复制为第三种浏览策略。

## 方案比较

### 方案 A：单一策略模块（采用）

创建 `taojinbi_task_strategies.py`，在一个文件中实现策略选择、策略上下文、策略结果和两种浏览动作。

优点是当前只有两种交互策略，模块边界清楚且迁移范围可控；测试可以直接覆盖完整策略行为。今后出现三种以上明显独立的交互策略时，再按相同接口拆成目录。

### 方案 B：每种策略单独一个文件

创建 `taojinbi_strategies/` 包，并为普通浏览和搜一搜分别创建文件。

边界最细，但当前只有两种策略，会引入包初始化、共享上下文和跨文件跳转，结构成本高于收益，因此暂不采用。

### 方案 C：只抽取策略名称和元数据

只把标题到策略名称的映射移出运行入口，具体浏览动作仍保留在 `taojinbi_ocr_immersive.py`。

改动最少，但不能解决运行入口同时承担策略实现的问题，不满足本次拆分目标，因此不采用。

## 模块职责

### `taojinbi_task_strategies.py`

负责：

- 定义稳定的策略标识；
- 根据已经通过安全筛选的标题选择策略；
- 执行普通信息流单轮浏览；
- 执行搜索发现单轮浏览；
- 返回结构化策略结果和具体失败原因。

该模块可以依赖 `taojinbi_ocr_ui.py` 中的纯识别函数，例如搜索入口、结果流和关键词候选识别；不得导入 `淘金币系/taojinbi_ocr_immersive.py`，避免循环依赖。

### `taojinbi_ocr_ui.py`

继续负责 OCR 文本解析、白名单与风险词筛选、候选按钮定位、搜索页面特征和安全坐标判断。它不执行设备动作，也不决定进度是否完成。

### `淘金币系/taojinbi_ocr_immersive.py`

继续负责设备连接后的安全读取、任务列表导航、任务进入与返回、进度回读、任务消失刷新、状态机适配、任务数量限制和结果汇总。它构造策略调用所需的上下文，但不再实现具体浏览手势。

### `taojinbi_task_core.py`

继续负责进度转换、连续失败、动态分母和任务完成状态机，不依赖 OCR 或设备。

## 接口设计

策略模块提供以下稳定接口：

```python
@dataclass(frozen=True)
class StrategyResult:
    ok: bool
    reason: str = ""


@dataclass(frozen=True)
class StrategyContext:
    device: object
    reader: object
    screen: tuple[int, int]
    read_screen: Callable[[], object]
    screen_is_safe: Callable[[object], bool]
    package_is_safe: Callable[[], bool]
    safe_tap: Callable[[tuple[int, int]], bool]


def select_task_strategy(title: str) -> str | None:
    ...


def execute_task_strategy(
    strategy: str,
    context: StrategyContext,
    browse_count: int,
) -> StrategyResult:
    ...
```

`StrategyContext` 通过回调复用运行入口现有的截图 OCR、安全屏幕检查、包名检查和安全点击能力，使策略模块不反向依赖运行入口。普通信息流保持现有行为，只在每次滑动前调用 `package_is_safe`；搜一搜使用 OCR 屏幕安全检查。时间等待和随机候选选择保留为模块内部实现，并在测试中使用标准库 mock 控制。

策略选择只在候选任务已通过 `find_safe_browse_target` 后调用：“搜一搜”结构选择搜索策略，其它已批准候选选择普通信息流策略。`execute_task_strategy()` 收到未知策略标识时返回失败结果，不执行任何点击或滑动；策略选择函数不得作为安全白名单使用。

## 调用数据流

1. OCR UI 从任务列表中识别并安全筛选 `BrowseTarget`。
2. OCR 运行入口重新定位并进入同一任务。
3. 运行入口调用 `select_task_strategy(title)`。
4. 运行入口根据当前进度计算普通策略的 `browse_count`；搜一搜策略忽略剩余分母，只完成一次已批准的“关键词 + 上下滑动”单轮动作。
5. 运行入口构造 `StrategyContext` 并调用 `execute_task_strategy()`。
6. 策略成功后，运行入口返回任务列表并交给现有进度状态机回读。
7. 策略失败时，运行入口尝试安全返回列表并停止本轮；不会进入下一任务。

## 失败与异常语义

- 未识别策略：`unknown_strategy`，不执行设备动作。
- 搜索入口不可读：`search_entry_unavailable`。
- 无可靠搜索发现候选：`discovery_candidate_unavailable`。
- 搜索结果流未出现：`search_result_unavailable`。
- 滑动前后包名或 OCR 风险检查失败：`unsafe_screen`。
- 普通浏览中离开淘宝：`unsafe_package`。
- 设备截图、OCR、点击、滑动或 RPC 抛出的异常不在策略层吞掉，继续由现有核心/入口异常边界统一转换为 `device_io_error`。

具体原因用于日志和测试，不改变现有“非确认结果停止当前任务”的外层语义。

## 兼容与迁移

- 先为新策略模块写失败测试，再创建最小接口和两种策略。
- 再写 OCR 运行入口集成失败测试，将 `run_one_safe_browse_task()` 改为调用策略模块。
- 删除运行入口中已经迁移的 `_wait_search_result_feed()`、`trigger_search_from_discovery()` 和 `browse_search_results_by_scroll()`，以及只为它们服务的导入。
- 早期专用 `run_immersive_goods_task_ocr()` 保留公共签名；如其浏览动作与普通策略重复，则改为内部调用 `feed_browse`，避免破坏旧调用方。
- 不移动 `utils.py` 中用户原有 SSL/EasyOCR 设置，不覆盖其历史修改。

## 测试策略

使用标准库 `unittest`，不连接手机：

1. “搜一搜”选择 `search_discovery_browse`，已通过安全筛选的其它标题选择 `feed_browse`，未知策略失败关闭。
2. 普通策略严格执行指定次数的停留和上滑，不调用点击。
3. 普通策略在包名安全检查失败时停止，且不继续滑动。
4. 搜索策略只点击一个 OCR 定位的“搜索发现”关键词，然后上滑一次、下滑一次。
5. 假设备对商品点击直接抛错，验证搜一搜没有商品详情点击路径。
6. 搜索入口不可读、候选缺失、结果流超时或滑动后风险检查失败时返回明确原因。
7. OCR 运行入口调用选中的策略；策略失败后安全返回列表并保持现有进度/恢复边界。
8. 现有 OCR UI、核心状态机、刷新恢复和入口安全测试保持通过。

离线验证包括目标测试、完整 `unittest discover`、相关 Python 文件编译和 `git diff --check`。本次结构重构不自动进行真机测试；离线通过后再由用户单独批准受控单任务验证。

## 完成标准

- 两类策略均由 `taojinbi_task_strategies.py` 实现并有独立测试。
- OCR 运行入口不再包含具体搜索发现或结果页浏览动作。
- 策略模块不导入 OCR 运行入口，不产生循环依赖。
- 行为、安全边界、等待与滑动参数保持不变。
- 所有现有测试与新增测试通过。
- 未操作真实手机，未推送远端。
