# coin11-tb 公开 Beta 与双仓库拆分设计

**日期：** 2026-08-21
**状态：** 用户已确认设计，等待书面审阅
**目标版本：** `v0.1.0-beta`

## 1. 目标

将当前包含多平台、历史活动脚本和内部进度记录的完整仓库拆分为两个用途明确的仓库：

- 私有仓库 `coin11-tb-full-private` 保存当前全部文件与完整历史；
- 新公开仓库 `coin11-tb` 以干净 Git 历史发布经过验证的淘金币 OCR 核心。

公开版不追求无人值守地执行所有淘金币任务。第一版只支持三个显式任务模块，默认一次最多执行一个任务，并在证据不足时停止。

## 2. 已确认的仓库生命周期

### 2.1 发布准备阶段

当前完整仓库继续作为临时开发工作区，用于完成公开 Beta 所需的模块化、可靠性、文档、测试和脱敏工作。准备期间不维护两份同步代码，也不推送当前领先远端的本地提交。

### 2.2 发布切换

达到发布门槛后：

1. 将现有 GitHub 仓库重命名为 `coin11-tb-full-private` 并设为私有；
2. 按公开文件白名单导出已经验证的核心代码；
3. 对导出目录执行敏感信息、依赖、安装和测试审计；
4. 初始化全新的 Git 历史；
5. 创建新的公开仓库 `coin11-tb`；
6. 推送并发布 `v0.1.0-beta`。

任何改变 GitHub 可见性、创建仓库、重写历史或推送的操作，都必须在执行前单独取得用户确认。

### 2.3 发布后

从公开版 `v0.1.0-beta` 起，新公开仓库是淘金币核心的唯一权威来源。私有仓库保留拆分前历史并继续容纳非公开脚本，但不与公开核心进行双向复制开发；需要引用公开核心时记录公开版本号或提交号。

## 3. 公开范围

### 3.1 唯一入口

公开版只提供 OCR 入口。旧版 `淘金币系/淘金币任务.py`、`淘宝多任务执行.py` 和 XML/UIAutomator 入口不进入公开仓库。

用户通过以下任一方式启动：

```powershell
python -m coin11_tb --serial DEVICE --dry-run
python -m coin11_tb --serial DEVICE --max-tasks 1
```

### 3.2 正式支持的任务

公开 Beta 和发布准备阶段的当前开发代码都只允许：

- `搜一搜…`
- `看看#…`
- `发现精选好物`

所有其他任务统一报告 `unsupported_task` 并跳过，不能因描述中出现“浏览”而自动获得权限。

### 3.3 明确移除的旧白名单

以下结构必须从 OCR 前缀、核心精确合同、描述例外和测试夹具中同步移除：

- `拍立淘…`
- `酒店超抵…`
- `去省钱卡领红包…`
- `淘金币充话费…`

原有的 `好物…`、`逛逛金币…`、`逛好店…` 等泛化前缀也不进入新的公开注册表。未来增加任务时，必须新增独立任务模块、离线测试和真机验收，不能直接扩充通用前缀。

### 3.4 不公开的内容

- `utils.py`
- `taojinbi_task_ui.py`
- 旧版淘金币入口和通用启动器
- 支付宝、闲鱼、天猫及历年淘宝活动脚本
- `img/` 旧模板素材
- `进度跟踪/`
- 含真实设备信息的内部计划、设计执行记录和真机审计文件
- 本地虚拟环境、OCR 临时截图和缓存

## 4. 公开仓库结构

```text
coin11-tb/
├─ src/
│  └─ coin11_tb/
│     ├─ __init__.py
│     ├─ __main__.py
│     ├─ cli.py
│     ├─ config.py
│     ├─ core.py
│     ├─ ocr_ui.py
│     ├─ strategies.py
│     ├─ runtime.py
│     └─ tasks/
│        ├─ __init__.py
│        ├─ registry.py
│        ├─ search.py
│        ├─ hashtag.py
│        └─ featured_goods.py
├─ tests/
├─ docs/
├─ pyproject.toml
├─ README.md
├─ LICENSE
├─ SECURITY.md
├─ CONTRIBUTING.md
└─ CHANGELOG.md
```

### 4.1 共享组件

- `core.py`：纯任务规则、进度状态机和结果模型；不导入设备或 OCR 后端。
- `ocr_ui.py`：解析 OCR 结果、定位文本和按钮、执行坐标与风险证据校验；不操作设备。
- `strategies.py`：实现共享的普通信息流浏览和搜索发现浏览动作；不决定任务是否被允许。
- `runtime.py`：连接设备、截屏、返回任务列表、刷新、进度回读和单任务编排。
- `config.py`：命令行和环境变量解析；不保存私人设备默认值。
- `cli.py`：唯一用户入口、退出码和顶层异常处理。

所有模块在导入时都不得连接手机、下载模型、启动应用或输出环境诊断。

## 5. 显式任务模块

每个任务模块只描述任务身份、策略、进度政策和额外安全要求。共享点击、滑动和 OCR 算法不能复制到任务模块中。

### 5.1 `tasks/search.py`

- 匹配规范化后以 `搜一搜` 开头的标题；
- 允许 OCR 偶发漏读同行“浏览”；
- 使用搜索发现策略；
- 随机点击一个位于“搜索发现”区域内、通过安全坐标校验的关键词；
- 进入结果流后只执行一次上滑和一次下滑；
- 不查找、不定位、不点击商品卡片；
- 接受任意初始分母，但同一轮中分母变化时停止并要求重新确认。

### 5.2 `tasks/hashtag.py`

- 匹配规范化后以 `看看#` 开头的标题；
- 允许 OCR 偶发漏读同行“浏览”；
- 使用普通信息流策略；
- `#` 后的文本只作为轮换标题，不扩大任务权限；
- 支持标题和分母随机变化；
- 检测到新周期、进度回落或身份轮换时停止，不跨周期继续执行。

### 5.3 `tasks/featured_goods.py`

- 规范化标题必须精确等于 `发现精选好物`；
- 同行描述必须可靠读取到“浏览”；
- 使用普通信息流策略；
- 分母以进入任务时读到的值为本轮固定目标；
- 分母变化或进度回落时停止。

### 5.4 `tasks/registry.py`

- 只注册上述三个模块；
- 全局外部应用词、交易词和风控词在任务模块匹配之前执行；
- 模块不能覆盖全局拒绝结果；
- 未注册标题返回 `unsupported_task`，记录标题和跳过原因且不点击；
- 注册顺序不能改变安全结果。

## 6. 运行和安全合同

### 6.1 默认行为

- 默认 `--max-tasks 1`；
- `--max-tasks 0` 只检查入口，不执行任务；
- `--dry-run` 可以截屏、OCR 和滚动任务列表，但绝不点击任务按钮；
- 必须通过 `--serial` 或 `TAOJINBI_DEVICE_SERIAL` 指定设备；缺失时停止；
- OCR 默认 CPU，GPU 必须显式启用；
- 单任务总期限默认 1200 秒；
- 任务行消失最多刷新 2 次，每次恢复都有独立期限并输出阶段日志。

### 6.2 失败关闭

以下任一情况停止当前任务，不寻找下一项：

- 当前包名为空、读取失败或不是淘宝；
- OCR 后端失败或关键文本置信度不足；
- 同一任务存在不唯一按钮；
- 点击前二次定位与初次定位不一致；
- 页面出现验证码、滑块、访问受限、操作频繁或其他风控词；
- 任务标题未注册；
- 任务行描述不满足对应模块合同；
- 进度不可读、回落、分母异常变化或任务周期轮换；
- 设备断连或 UI RPC 异常；
- 单任务或恢复阶段超过期限。

任何命令行参数都不能开放第三方应用、交易、充值、邀请、游戏、红包、外卖、助力、评价、关注、收藏、加购或购买任务。

### 6.3 中断处理

收到 `Ctrl+C` 后立即停止新的点击和滑动。只有在设备仍连接、前台包名仍为淘宝且页面未出现风险证据时，才允许执行一次有界的任务列表恢复；否则直接退出。

### 6.4 日志

日志使用 UTF-8 并包含时间、任务模块、阶段、进度和停止原因。至少覆盖：

- 列表扫描和滚动；
- 候选接受/拒绝及原因；
- 点击前二次校验；
- 策略开始/结束；
- 返回任务列表；
- 进度回读；
- 任务消失刷新；
- 超时、中断和安全停止。

日志不得记录账号、手机号、Cookie、截图内容或完整设备序列号。设备标识只允许使用脱敏后缀。

### 6.5 退出码

- `0`：正常完成或 `--dry-run` 正常结束；
- `2`：参数或设备配置错误；
- `3`：安全边界触发；
- `4`：设备或 OCR 运行异常；
- `5`：任务执行过但完成状态未确认。

## 7. 数据流

1. CLI 解析参数并验证设备配置；
2. runtime 截屏并取得 OCR spans；
3. 全局安全门检查淘宝包名和风险文本；
4. registry 使用任务模块匹配结构化任务；
5. 未注册或证据不足的任务只记录跳过原因；
6. `--dry-run` 在候选报告后结束，不进入任务；
7. 正常模式在点击前重新 OCR 定位同一任务和唯一按钮；
8. runtime 调用任务模块指定的共享策略；
9. runtime 有界返回列表并回读进度；
10. core 根据模块进度政策判断完成、继续、轮换或未确认；
11. 非确认结果停止批次，只有确认完成才允许在显式上限内寻找下一项。

## 8. 实施顺序

所有行为变更使用标准库 `unittest` 进行 TDD，先观察测试因缺少目标行为而失败，再编写最小实现。

1. 建立公开包骨架、任务合同与 registry 默认拒绝；
2. 完成 `搜一搜` 模块并移除旧泛化入口；
3. 完成 `看看#` 模块和动态周期政策；
4. 完成 `发现精选好物` 模块和严格描述合同；
5. 集成 runtime、`--dry-run`、期限、日志、退出码和中断处理；
6. 完成依赖、CLI、用户文档和 CI；
7. 完成离线、全新环境和受控真机发布验收；
8. 最终脱敏导出并在单独授权后执行 GitHub 仓库切换和发布。

每完成一个任务模块，必须独立通过离线测试和受控真机验收，才能在 registry 中启用下一个模块。

## 9. 测试与发布门槛

### 9.1 离线基线

当前公开依赖闭包的四组测试共 `168/168` 通过。包迁移后必须保持这些行为，并新增：

- registry 只接受三个模块；
- 所有旧白名单结构返回 `unsupported_task`；
- 三个任务模块各自的匹配、描述和进度政策；
- `--dry-run` 零任务点击；
- 缺失设备参数安全失败；
- 总期限和恢复期限；
- UTF-8 日志与脱敏设备标识；
- `Ctrl+C` 和设备断连；
- 五种退出码映射。

所有公开 Python 文件必须编译通过。测试不得连接真机或下载 OCR 模型。

### 9.2 全新环境和 CI

- 声明支持 Python 3.11；
- 从空虚拟环境按 `pyproject.toml` 安装成功；
- 直接依赖必须显式声明，不能依赖偶然的传递安装；
- GitHub Actions 至少在 Windows 和 Linux 上运行离线测试；
- CI 不需要 ADB 设备，也不运行真实任务。

### 9.3 真机验收

- `搜一搜` 至少一次确认进度增长，且无商品详情点击；
- `看看#` 至少一次确认进度增长，并验证标题/分母轮换停止；
- `发现精选好物` 至少一次确认进度增长；
- 任务消失刷新最多两次且不会长时间无日志；
- 外部应用、交易和未注册任务整屏扫描均无任务点击；
- 设备断连、风控和人工中断均安全退出；
- 真机阶段始终从 `--max-tasks 1` 开始。

### 9.4 脱敏和发布审计

- 公开文件中不存在真实设备序列号、局域网地址或本机绝对路径；
- 不存在密码、Token、Cookie 或 API Key；
- 公开 Git 历史从一个经过审计的初始提交开始；
- README 准确描述支持范围、安装步骤、安全限制和已知问题；
- Apache-2.0 LICENSE、SECURITY、CONTRIBUTING 和 CHANGELOG 完整；
- 发布前再次比较公开文件清单，不允许白名单外文件进入仓库。

## 10. 非目标

- 不执行或支持第三方应用任务；
- 不执行交易、充值、邀请、游戏、红包、外卖或社交互动任务；
- 不绕过验证码、滑块或风险控制；
- 不通过 OCR 坐标点击商品卡片；
- 不承诺无人值守完成全部任务；
- 不在本设计中继续维护旧版入口或其他平台脚本；
- 不在用户单独批准前修改 GitHub 仓库设置、创建远端、推送或发布。
