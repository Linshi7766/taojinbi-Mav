# 淘金币任务消失后的刷新恢复设计

## 背景

OCR 任务执行过程中，任务详情页返回任务列表后，任务行可能因为任务完成、随机刷新或列表未及时加载而暂时不可见。当前逻辑在得到 `task_row_unobserved` 后停止，导致仍有机会继续完成的淘宝内部纯浏览任务无法恢复。

用户希望在这种情况下：退出当前页面，回到淘金币页面，重新点击“赚更多金币”，滚动任务列表，再检查任务是否刷新。刷新后如果同名任务仍未完成，脚本可以继续执行，但最多刷新两次。

## 目标

- 仅对已经进入并浏览过、返回后明确得到 `task_row_unobserved` 的任务触发刷新恢复。
- 每个任务最多执行两次刷新恢复尝试。
- 每次尝试都通过 OCR 动态识别“赚更多金币”和任务行，不使用固定坐标。
- 刷新后找到同名且进度未完成的安全任务时自动继续；任务已完成时停止并记录结果。
- 刷新后仍未找到任务时停止当前任务，不自动点击下一个任务。
- 设备异常、非淘宝包名、风控页面、外部应用或不安全任务一律停止，不触发刷新。
- 所有刷新尝试、任务匹配、最新进度和停止原因可审计输出。

## 非目标与安全边界

- 不执行第三方应用任务（头条、支付宝、蚂蚁森林等）。
- 不执行下单、购买、邀请、充值、助力、游戏、红包抢领、外卖等任务。
- 不绕过验证码、风控或任何安全验证。
- 不增加 OCR 坐标点击以外的点击通道；坐标必须来自当前屏幕 OCR 且经过安全区域校验。
- 不因为 OCR 暂时不可用或设备 I/O 异常而重复点击。

## 方案选择

### 方案 A：在主循环中直接插入两次重试

在 `run_one_safe_browse_task` 返回 `task_row_unobserved` 后直接调用返回、点击入口、滚动和重读逻辑。

优点是改动少；缺点是设备导航、入口识别、匹配和重试状态会混在任务执行主循环里，难以对调用顺序和“不超过两次”做离线测试，后续容易重复点击。

### 方案 B：独立的有界刷新恢复助手（采用）

新增一个只负责编排刷新恢复的设备层助手，由主任务函数提供当前任务标题、屏幕尺寸和 OCR/点击回调。助手每次按固定顺序执行：

1. 确认仍在淘宝且当前屏幕无风控标记；
2. 按返回键直到 OCR 确认回到任务列表；
3. OCR 定位并安全点击“赚更多金币”；
4. 等待“赚金币抵钱”列表锚点出现；
5. 在任务栏滚动一屏并等待渲染；
6. 用标题等价规则重新定位任务并读取进度；
7. 返回“未完成可继续”“已完成”“未找到”或“安全失败”。

主任务函数最多调用该助手两次；“未完成可继续”才重新进入任务并交回既有进度状态机。这样可以用假设备和假 OCR 验证完整调用顺序，不需要真实手机才能覆盖边界。

### 方案 C：所有缺少进度的情况都重新打开列表

对 `missing_progress`、`progress_unreadable`、`task_row_unobserved` 统一刷新。

该方案可能把 OCR 暂时失败、任务完成后消失和真实列表刷新混为一谈，会增加无意义点击和风控风险，因此不采用。

## 详细行为

### 触发条件

刷新恢复只在以下条件同时满足时启动：

- 已经成功进入过目标任务并至少完成一次浏览动作；
- 既有进度状态机返回 `task_row_unobserved`；
- 当前设备包名是 `com.taobao.taobao`，且当前屏幕不含风控标记。

其它原因保持现有 fail-closed 行为。

### 标题匹配

- 普通任务使用现有 `titles_equivalent` 规则比较完整标题。
- `看看#` 任务按 `看看#` 结构比较，允许商品名随机变化，但必须仍是淘宝内部“看看#”浏览任务。
- 重新定位必须同时读到任务标题、有效 `x/y` 进度和安全的“去完成”按钮；缺少任一信息即视为未找到，不点击。

### 重试与停止

- `refresh_attempt` 从 1 到 2；每次只刷新一次列表并只尝试续跑一次。
- 任务已完成：记录完成，不再刷新或进入。
- 任务未完成且可安全定位：自动继续既有浏览流程。
- 两次都未找到：返回 `refresh_not_found`，加入未完成审计，不继续其它任务。
- 任意安全失败：立即返回具体原因，不消耗剩余刷新次数。

### 日志

每次尝试至少输出：任务标题、尝试次数、是否成功回到列表、是否点击“赚更多金币”、是否找到任务、最新进度/分母及停止原因。日志不得打印或点击外部应用任务。

## 文件与接口

- 修改 `淘金币系/taojinbi_ocr_immersive.py`：实现刷新恢复助手、在 `task_row_unobserved` 分支接入最多两次恢复，并复用现有返回列表、OCR 安全校验、任务进入和进度状态机。
- 如需抽取通用“赚更多金币”OCR 定位，最小修改 `taojinbi_ocr_ui.py`；不改变现有白名单和安全标记语义。
- 修改 `tests/test_taojinbi_ocr_runtime.py`：先添加失败测试，覆盖调用顺序、两次上限、任务匹配、续跑和 fail-closed。
- 更新 `README.md` 或 `进度跟踪/`：记录刷新恢复边界和真机验证结果；不修改 `utils.py`。

## 测试策略

使用标准库 `unittest` 和注入的假设备/OCR 回调，不新增依赖：

1. `task_row_unobserved` 触发一次完整的退出、点击、滚动、读取序列。
2. 第一次未找到、第二次找到时最多两次且自动续跑。
3. 两次均未找到时返回 `refresh_not_found`，不点击第三次、不执行下一个任务。
4. `看看#` 标题随机变化仍能匹配；普通标题不误匹配。
5. 已完成任务不续跑；第三方包名、风控屏幕、OCR 不可用和设备异常均不点击入口。
6. 现有离线全量测试保持通过。

真机只做单任务、只读/受控验证：确认任务消失后最多两次刷新，确认动态按钮识别与安全停止；不执行全部任务批次。
